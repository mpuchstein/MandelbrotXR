## Judges

| Folder | Material | Special-elements focus |
|---|---|---|
| `HTML-Judge/` | the 8 HTML files, static analysis only | features others lack, libraries or techniques no one else uses |
| `TRANSCRIPT-Judge/` | the 8 anonymized chat transcripts | explanations of what was built, reasoning for decisions, hallucinations |
| `HTML_TRANSCRIPT-Judge/` | HTML + transcript per candidate | special features, differences from the norm, claims vs code |
| `Browser-Judge/` | hands-on in Claude in Chrome, no source | what sets a product apart |
| `Browser_HTML-Judge/` | hands-on in Chrome + source | how the code shaped the observed result |

Each folder contains:
- `PROMPT.txt`: the exact prompt, saved before launch and checked against the agent's logged first message.
- `RANKING.md`: the judge's output, verbatim: criteria, a ranked table with justifications under 50 words, special elements with a one-sentence reason each, and a summary under 200 words.
- `TRANSCRIPT.md`: the agent's session log, rendered and redacted.
- `MAPPING.md`: letter → folder, plus the result of an automated format check (all 5 passed).
- `screenshots/`: the browser judges only.

## Method
- **Model:** each judge was a `general-purpose` subagent on Opus 5.5 with effort `high`, the same effort the phase-1 reviewers actually ran at.
- **Blinding:** each judge had its own seeded shuffle onto the letters A–H (`../ReviewOrchestrator/tools/judge_blind.py`; seeds 101/202/303/404/505). The judges saw only their own scratch folder, not this repo. Transcripts were anonymized with the same function as in phase 1. HTML copies are byte-identical to the sources, except for the one patch below.
- **Prompt versions:** both prompts went to every judge, with a letter → version table. Each candidate was judged against its own prompt, in one combined ranking.
- **Native dialogs:** only `GitHub-CopilotTasks-Auto-Autopilot-v1` calls `alert(` (2 calls).
  - The **browser judge** never saw code. It got copies where those 2 calls were rewritten to `console.log(`, and its prompt said so.
  - The **browser + HTML judge** got the original files and was told to find the dialog calls in the source and override them at runtime with `console.log`. Both judges reported that candidate's native dialogs.
- **Serving:** one `python3 -m http.server` per candidate and origin, on ports 8801–8808 (browser judge) and 8901–8908 (browser + HTML judge). The server logs show every port was requested.
- **Scheduling:** the three static judges ran in parallel with the browser judge. The browser + HTML judge ran afterwards, because the two browser judges share one browser.
- **Environment limits:** desktop Chrome without an XR device or emulator, and a window manager that would not resize below about 446 px (the judges used a 390×844 iframe instead). No real VR or AR session was entered.

## Incidents
- **Over-redaction:** `redact.py` had moved into the repo, so its "files we created" exclusion no longer covered the scratchpad. In the browser judge's first render, `ls` output for the folders A–H became redaction terms, and single letters were replaced. The prompt-fidelity check caught it. The fix added a minimum term length of 6 and treats the scratchpad as an own root. All judge transcripts were re-rendered, with no false redactions.
- **Log lookup:** `judge_finalize.py` first looked for `agentName` only on the first log line; it now scans until it finds it.
